# Update the existing Windows Stage 2 Research Lab

This update fixes the Capture Studio textarea crash and distinguishes workspace rendering failures from failed backend requests. It includes the four corrected source files and two regression tests. No dependency changes, CameraX edits or dataset changes are required. The existing Lab remains your application.

The connected GitHub repository is `shahedahammod490-png/1st`. It currently stores the Lab baseline as archives; ordinary `git pull` of those archives alone does not update an already extracted Windows Lab. Use this updater to apply only the reviewed files to that existing Lab. The original archives stay unchanged.

## Beginner steps (ZIP download; Git is optional)

1. In the GitHub repository, choose branch `fix/capture-studio-textarea`. Click the green **Code** button, then **Download ZIP**. Extract it into a new Downloads folder, separate from your Lab and original OcuRisk. After the PR merges, the same update will be available on `main`.
2. Find your existing **Research Lab** folder: it contains `ocurisk_lab`, `requirements.txt`, `.venv`, and usually `data`. Record the data directory used by your existing server. Do not choose the original EYE/OcuRisk project.
3. In the terminal running the Research Lab, press **Ctrl+C**. Keep the same data directory when restarting. For added assurance, make a separate backup copy of your research data while the server is stopped.
4. Open PowerShell. Replace the two example folder paths below with your actual folders. Use the Lab's existing Python, so no additional installation is needed:

```powershell
$labDir = 'C:\Users\YOUR_NAME\Documents\OcuRisk-Research-Lab'
$updateDir = 'C:\Users\YOUR_NAME\Downloads\1st-fix-capture-studio-textarea\updates\capture-studio'
& "$labDir\.venv\Scripts\python.exe" "$updateDir\apply_capture_fix.py" --lab-dir "$labDir"
```

The updater verifies file hashes, backs up source files under `.capture-fix-backups`, and refuses to overwrite unrecognized local edits. It is safe to rerun: already installed files are skipped. If it reports local edits or a different version, stop and preserve those files; do not force an overwrite.

5. Restart from your existing Lab directory with the **same data folder as before**. If the existing folder is named `data` inside the Lab, run:

```powershell
Set-Location "$labDir"
& "$labDir\.venv\Scripts\python.exe" -m ocurisk_lab.server --host 127.0.0.1 --port 8765 --data-dir "$labDir\data"
```

If your prior server used a different data directory, substitute that exact path for `--data-dir`. Do not run two services against the same data directory. Keep this terminal open.

6. In another PowerShell window, verify the service:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health
```

It should show `status: running`. Open your browser at `http://127.0.0.1:8765`, press **Ctrl+F5**, and click **Capture Studio**. Research notes should be editable and the top status should say **Local service connected**.

7. Create a nonhuman test experiment, start your existing DroidCam phone/Windows client, click **Discover cameras**, select the actual DroidCam input, and request preview permission. Record a short inert-target clip, stop it, and check autosave/automatic analysis. No custom Android APK is needed for this workflow.

## If you already cloned this GitHub repository

In that clone, first run `git status`. Preserve any local changes. Then:

```powershell
git fetch origin
git switch --track origin/fix/capture-studio-textarea
```

If that local branch already exists, use `git switch fix/capture-studio-textarea` followed by `git pull --ff-only`. Set `$updateDir` to `<your clone>\updates\capture-studio`, then follow steps 2–7 above. Do not use `git reset --hard` or `git clean`; an extracted Lab is not automatically updated by Git.
